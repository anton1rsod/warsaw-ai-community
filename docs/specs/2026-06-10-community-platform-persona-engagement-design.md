# Community Platform — Persona engagement + member-page redesign (v0.12 design)

**Date:** 2026-06-10 · **Status:** Implemented in v0.12.0 (spec §23; this doc is the design record. Routing note: §3's "anon viewers" line describes render states only — `/members/[slug]` stays auth-gated per spec §23 "Routing posture", Anton-decided 2026-06-11) · **Scope owner:** community-platform

**Approved mockup:** [`community/brand/explorations/2026-06-10-member-page-typeset-dossier-mockup.html`](../../community/brand/explorations/2026-06-10-member-page-typeset-dossier-mockup.html) (open directly in a browser)

## 1. Context & goal

v0.11.1 shipped persona attach + rich card. Anton's brief: make the persona section *usable, fun, engaging, meaningful for an IT community* — and the current card reads as "a rendered file" (metric tiles → placeholder prose → uppercase chip walls → raw markdown). Research across developer-identity products (Read.cv, Peerlist, GitHub, daily.dev, Linear) + 2026 design-trend audits confirmed the diagnosis: heavy borders everywhere, uniform chip soup, and hierarchy-by-boxes are documented dated-tells; loved profiles converge on a narrow typeset column where whitespace is the hierarchy.

**Primary success metric (Anton-locked): conversations started** — members talk to each other because of personas (lens clicks → Telegram pings, questions asked/answered). Not coverage, not evaluations-count, not meetup wow — those are secondary effects.

## 2. Decisions (D1–D9, Anton-locked in this brainstorm)

- **D1 — Purpose frame:** mix of "two-layer live+deep" and "persona = THE member profile centerpiece." The deep persona (45-60 min interview artifact) stays the backbone; the member page reorganizes around it as one designed identity surface.
- **D2 — Persona as the member's interface:** the chosen interaction set treats the persona as something peers *use*: diff it (overlap lens), query it (ask-me-about → Q&A), route work to it (evaluator routing), simulate it (persona-as-lens AI), carry it (shareable card). Soft-social garnish (vouches, first-question wall, asks/offers fields) was considered and not picked.
- **D3 — Supply stays external:** NO in-platform persona builder ("at least not yet" — Anton). Personas are created via the persona-builder interview and attached by the member. New attach affordance: **attach-by-GitHub-link** (raw GitHub/gist URL fetched server-side through the *identical* validation path as paste) + a stored source URL enabling **"re-sync from source"** — which becomes the persona *update* path and kills the staleness problem. Precedent: "Personas v2 (external repos)" in V0_5_BACKLOG.
- **D4 — Phasing (Approach 1, "conversation engine, staged"):**
  - **v0.12:** member-page redesign (this doc §3-§4) + overlap lens + ask-me-about chips (read-only) + shareable member card (OG image) + GitHub-link attach/re-sync. Zero new consent surface.
  - **v0.13:** persona Q&A write path (questions on personas, git-stored via bot, member answers/hides; light rules).
  - **v0.14:** idea → evaluator routing (tag-match scoring + request flow; = spec §22's deferred discovery item, cleanest H144 consent fit).
  - **v0.15:** persona-as-lens AI — gated behind its own ADR + per-member opt-in + LLM-infra decision. Boldest move, done last because it's the only one that can damage trust if botched.
- **D5 — Visual direction: "typeset dossier."** Read.cv skeleton (narrow editorial column, ledger rows, ink ladder), Anthropic-style warm-editorial skin (cream canvas, near-black warm ink, warm-tinted hairlines), Vercel-style mono kickers (the platform's existing `//` idiom). One expressive moment: the member's `my_typical_first_question` as a pull-quote with a hanging amber asterisk (the brand mark doing typographic work).
- **D6 — Volume calibration (3 mockup rounds):** v2 "too quiet" → v3 (dark band, asterisk separators, member numbers) "previous was better" → **v4 approved**: v2 skeleton + 38px name + 22px statement only. Loud moves explicitly rejected: dark ink quote-band, amber asterisk separators in chip rows, gradient avatar, `subploter #001` numbering.
- **D7 — Chips are gone on the member page.** Expertise renders as definition-list ledger rows (mono label gutter: EXPERT / PRACTITIONER / NICHE / LANGUAGES; inline comma-lists right; depth hierarchy by tone — expert 500-weight ink, practitioner muted). `Tag`/chip components stay for other surfaces; this page drops them.
- **D8 — Progressive disclosure for the deep persona:** one-line bio → 22px statement under the name; career arc visible with gradient-fade + "continue reading"; Hard-won knowledge / Patterns / Role dispositions as styled `<details>` rows with counted headers and carets. Never hide the primary bio.
- **D9 — Contributions demoted:** the 4-metric-tile ContributionCard leaves the top of the page; a single mono stat line in the footer (`5 commits · 19 ADRs · 1 status post · ✓ meetup-4 · ♥ thanked 0×`) carries the evidence quietly.

## 3. Visual spec (from the approved mockup)

**Tokens.** Existing: `--cream #fef6e6`, `--cream-deep #fdebc9`, `--ink #1a1a2e`, `--dust #886c37`, `--accent-500 #f59e0b` (amber), `--accent-700 #b45309` (amber-deep, link color on cream — 4.67:1 AA). New derived warm ladder (every neutral tinted warm, same hue family):
- `--ink-body #3c3a47` (body text) · `--ink-muted #6e6757` (secondary; 5.22:1 on cream, 5.02:1 on surface-soft — the only muted tone safe on ALL page surfaces)
- small-text muted = **dust** `#886c37` on cream ONLY (4.60:1 AA); on `--surface-soft` dust drops to 4.42:1 (FAIL) → tinted surfaces use `--ink-muted`. `#99906f` measured 2.97:1 and FAILED. **Contrast is pinned per (foreground × background) PAIR, not per token, including hover/focus states** (verified: summary:hover's soft background + lens band were both sub-AA with dust/amber-deep — mockup patched).
- `--accent-700 #b45309` (amber-deep): link color on cream 4.67:1 AA; **4.49:1 on surface-soft (sub-AA)** → lens-band links render `--ink` with an amber underline instead.
- `--hairline #f1e4c8` · `--hairline-strong #e3d2ac` (cream darkened ~6%, never gray; ` · ` separators in this tone are decorative → `aria-hidden`)
- `--surface-soft #fdf1d9` (lens band + summary hover; the only tinted panel on the page)

**Type.** Geist display 600 (name 38px/-0.025em; statement 22px/500/-0.018em), Inter body 16px/1.55 + 15px in ledger rows, JetBrains Mono for kickers (11px/500/uppercase/+0.09em/dust), metadata (12px), pull-quote (19px), stat footer (12px). No bold-700 anywhere. No serif. No italic paragraphs.

**Layout.** 640px single centered column (24px gutters), 56px section rhythm, 64px top pad. Nav chrome constrained to the same 688px grid (hairline runs full-width). At ≥1080px, section kickers move to the left margin as right-aligned catalog labels ("archival index" marginalia). Mobile <560px: nav links collapse to `≡` (real platform: existing HeaderMobileMenu), ledger rows stack label-over-value, name 30px/statement 19px. Verified overflow-free at 375 (Playwright `scrollWidth: 375`).

**Containers.** No bordered boxes. Grouping by whitespace + 1px warm hairlines. Radius only on interactive/soft elements (lens band 10px). No shadows. Hover: links underline (130ms), `<details>` summary gets one `--surface-soft` step. `:focus-visible` = 2px **amber-deep** (`--accent-700`) ring, offset 2px — verified: raw amber `#f59e0b` is 2.0:1 on cream and fails SC 1.4.11 (non-text 3:1); amber-deep clears 3:1 on every page surface (4.67/4.49/4.22).

**A11y implementation constraints (adversarially verified 2026-06-10):**
- **Kickers ARE the headings.** Each section kicker renders as `<h2 class="kicker">` — one element doing visual + semantic duty. Never `aria-hidden`, never a parallel sr-only heading (drift trap): they are the page's only section labels, and hiding them would leave no heading structure below the h1 (SC 1.3.1). The decorative `// ` prefix wraps in `<span aria-hidden="true">`; uppercase via CSS `text-transform` over sentence-case source text. The lens band is `aria-labelledby` its kicker, whose `you × anton` gets an sr-only alternative ("overlap: you and Anton") so AT doesn't announce "multiplication sign". Heading-outline regression test (h1 → h2 per section). Absolute-positioning kickers into the margin at ≥1080px is AT-safe (DOM order unchanged).
- **`<details>`/`<summary>`:** keep `list-style:none` + `summary::-webkit-details-marker{display:none}` (Safari needs the latter); custom `.caret`/`▾`/decorative counts are `aria-hidden`; **never `display:contents`** on details/summary or wrappers (current WebKit bug renders expanded content inaccessible); **no heading elements inside `<summary>`** (summary maps to `role=button`; child heading semantics are dropped); summary text must read sensibly without expanded/collapsed announcements (AT support is inconsistent once the native marker is hidden). Closed `<details>` auto-expand on find-in-page in current Chrome/Firefox/Safari — older-browser degradation accepted. VoiceOver (macOS + iOS) pass required at ship smoke.
- **Career-arc gradient-fade:** "continue reading" must be a real toggle un-clipping the *same* DOM text (no duplicate node); on JS failure, default to expanded.
- **Hit areas (SC 2.5.8):** standalone mono action links (`.actions a`, `.more`, lens link, crumb) get min-height 24px via `padding-block` (visual size unchanged); regression test asserts ≥24px boxes at 375 and 1280 viewports.
- **Avatar initials** are decorative (`aria-hidden`; the name is adjacent in the h1) and use `--ink-muted` on cream-deep (dust measured 4.22:1 there).

**Page order (signed-in viewer):** `← members` crumb → identity (68px initials avatar on cream-deep + name + mono meta line) → 22px statement (persona `one_line_bio`) → quiet action row (`view card ↗` · `ask anton about… →`) → **overlap lens band** → `// expertise` ledger (expert/practitioner/niche/languages) → first-question pull-quote (hanging amber `*`) → `// evaluation posture` ledger (bullish when / skeptical when) → `// story` (career arc faded + details rows) → mono activity footer. Anon viewers: same page minus the lens band and minus self-only affordances. Profile-body markdown (if the member wrote one) renders inside `// story` above the persona narrative.

## 4. v0.12 functional scope

1. **Member-page redesign** per §3 — restructures `app/members/[slug]/page.tsx` + `PersonaPanel` into the typeset-dossier composition. Persona sections come from the *known* heading skeleton of `.public.md` (`## Background` → one-line bio / career arc / hard-won knowledge / patterns; `## Evaluation posture` → bullish / skeptical / failure+success patterns / first question; `## Role dispositions`) parsed into components, with **graceful fallback**: unknown/missing sections render as `.prose-warm` markdown exactly as today (H148 posture preserved — the parser never crashes, never truncates).
2. **Overlap lens** — signed-in viewers with their own persona see shared tags, complementary depths ("expert where you're familiar"), and 2-3 rule-derived conversation starters. Pure build-time/render computation on two parsed personas; viewer-private (not stored, not logged). Hidden for anon viewers and viewers without a persona.
3. **Ask-me-about chips** — derived from niche tags (read-only); `ask anton about… →` action deep-links to the member's preferred contact (Telegram handle if roster carries it — note: roster Telegram/Link/Focus columns are currently parsed-away in `lib/roster.ts`; v0.12 surfaces them) with a prefilled topic. No new write path.
4. **Shareable member card** — `app/members/[slug]/opengraph-image.tsx` (Next.js metadata **file convention**, not a hand-rolled route) using `ImageResponse` from `next/og`, rendering name + statement + top expert tags + wordmark on cream; `export const alt/size/contentType`; the default-export Image function **awaits the `params` Promise** (Next 16 breaking change). Next auto-injects the og:image meta — no `generateMetadata`/`metadataBase` wiring (the app currently has neither). The same URL (`/members/<slug>/opengraph-image`) IS the embeddable card for the `view card ↗` copy-snippet — GitHub camo just fetches it; no second route. **Verified constraints:** Node runtime (App Router default — do NOT set `runtime='edge'`; the `readFile` asset pattern needs Node); satori accepts only **ttf/otf/woff, NOT woff2**, so the `next/font/google` Geist is unusable here — vendor 1-2 static-weight Geist/GeistMono TTFs from the `geist` npm package (`dist/fonts/`, OFL-1.1) and pass via the `fonts` option (avoid the variable TTF; satori's axis handling is unreliable); wordmark embeds as base64 data-URI `<img>` from the path-drawn SVG; total under the 500KB ImageResponse bundle limit; confirm the vendored files trace into the function bundle (`outputFileTracingIncludes` if the readFile path isn't statically analyzable). **Caching:** the OG file is its own specialized Route Handler — the page's `force-dynamic` does NOT propagate; ImageResponse defaults to immutable max-age CDN caching, which is correct here: persona attach/re-sync/erasure land as commits → redeploy busts the CDN cache (third-party scrapers cache previews independently — accepted). **Privacy (verified gap):** the route is public and unauthenticated, so it must **re-apply the H147 `persona_visible` gate + H146 erasure state server-side** — hidden/absent persona ⇒ name-only fallback card, unit-tested like the page-level H147 test. Renders only `one_line_bio` + expert tags; never persona body text.
5. **GitHub-link attach + re-sync** — PersonaEditor gains a URL field (alternative to paste/upload), then the SAME `SavePersonaSchema`/H142 validation as paste. **URL guard, OWASP-verified, run on EVERY fetch:** parse with the WHATWG `URL` parser; require `protocol === "https:"`; require empty `username`/`password` (defeats `https://raw.githubusercontent.com@evil.com/…`, which parses to hostname `evil.com`) and empty `port`; `hostname` (parser-lowercased + punycode-normalized) must be **exactly** in the frozen Set {`raw.githubusercontent.com`, `gist.githubusercontent.com`} — strict `===` membership, never startsWith/includes/endsWith/regex (lookalike `raw.githubusercontent.com.evil.com` fails exact match); reject on any parse error. `redirect: "manual"` → any redirect rejects (verified: legitimate raw/gist URLs don't redirect). **Byte-accurate cap (verified: a Content-Length check alone is wrong):** stream the response counting received bytes; abort + discard the moment the count exceeds 65,536 — Content-Length is advisory and origin-controlled (early-reject on an oversized declaration, never rely on it); AbortController wall-clock timeout. For parity, `SavePersonaSchema`'s cap should validate UTF-8 byte length (`TextEncoder`) instead of `z.string().max(65536)` UTF-16 code units (which currently admits ~3× bytes for non-ASCII). Content-Type acceptance (`text/plain`/`text/markdown`/absent) is defense-in-depth only — raw/gist serve `text/plain` for everything; the authoritative content gate stays schema + H142 + the H143 sanitizer. **Pinned vs latest (verified):** a gist Raw-button URL pins a revision SHA (`…/raw/<sha>/<file>`) — re-syncing a pinned URL is a permanent no-op; normalize to the latest form (`…/raw/<file>`; branch refs for repo raws) before storing, or explicitly warn the member. **Re-sync TOCTOU (verified gap):** `persona_source_url` (location per O4) lives in publicly-editable git and is **untrusted on every read** — re-sync re-runs the identical URL guard before each fetch (never trusts attach-time validation), derives the slug from the session (H140 parity), and writes only the slug-derived path; a stored URL failing the guard errors cleanly with no fetch. Erasure (H146) also clears `persona_source_url`.
6. **i18n the PersonaEditor status strings** (carried from the v0.11.2 candidate list) + the new strings.

**Consent posture:** no change to ADR-0019. Everything renders/derives from already-public `.public.md` + profile data; link-attach is the same consent act through the same validation; H138–H150 invariants all hold. The lens is viewer-private computation. (The §22 known overhang — the separate ADR + history audit for pre-existing full-`.md` files — remains open and is NOT this scope.)

**Hardening candidates for spec §23 (final ids at spec lock; all standards-verified 2026-06-10):**
- URL guard on link-fetch: WHATWG parse + https-only + empty userinfo/port + exact-`===`-Set hostname allowlist + `redirect:"manual"` + parse-error reject (§4.5 wording is normative).
- Streamed byte-count cap (65,536 bytes) on the fetch body; Content-Length advisory-only; AbortController timeout; byte-accurate schema parity via `TextEncoder`.
- Re-sync treats `persona_source_url` as untrusted on every read: full URL guard re-run at fetch time (stored-URL TOCTOU), session-derived slug ownership, slug-derived write path only.
- Re-sync + link-attach share the single validation pipeline with paste (no second path).
- OG route re-applies H147 `persona_visible` + H146 erasure server-side (unauthenticated endpoint); hidden ⇒ name-only fallback card (unit-tested); renders `one_line_bio` + expert tags only.
- Contrast pinned per (foreground × background) **pair** incl. hover/focus states — regression test enumerates dust×{cream}, ink-muted×{cream,surface-soft}, amber-deep×{cream}, focus-ring×{cream,surface-soft,cream-deep}; lens band and summary-hover use `--ink-muted` (dust/amber-deep are sub-AA on surface-soft).
- Kickers-as-headings: `<h2 class="kicker">` single-element semantics (never aria-hidden, no sr-only twin); `// ` prefix aria-hidden; heading-outline test h1→h2-per-section.
- `<details>` constraints: no `display:contents`, no headings in summary, aria-hidden carets/decorative counts; VoiceOver pass at smoke.
- SC 2.5.8: 24px min hit-areas on standalone mono action links via padding-block, with a bounding-box regression test.
- Lens computed per-request for the viewer, never persisted/logged.

## 6. Research artifacts (for the plan-writer)

Three research briefs (developer-identity product teardowns with measured CSS values; sleek-craft rules from Linear/Vercel/Stripe/Anthropic teardowns; 2026 profile-trend do/don't audit) were produced in-session. Key conclusions are baked into §3; the do/don't table worth re-reading at implementation time: single-column editorial flow / no bento tiles · small confident avatar / no hero headshot · inline comma lists + definition rows / no chip walls · mono 12-13px muted metadata · one oversized statement max · gradient-fade + counted `<details>` / never accordion the bio · hairlines + whitespace / no nested cards · hover reveals only on expandables / no scroll-jacking.
